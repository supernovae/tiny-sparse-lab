# DevMind v1 — staged dense pilot protocol

Protocol identity: `devmind-pretrain-v1/pilot-1`, declared before seeing any v1 tokenizer or model outcomes. This supersedes the *proposed next test*, not the immutable `devmind-v0` releases, eleven card files, failed tokenizer attempt or [`source-survey-1`](source-survey.md). The prior 150-million-distinct-token, 90–120M-parameter, 201,326,592-target plan remains a **DATA_RICH** proposal, not a prerequisite for an exploratory dense MODEL-0. A PILOT cannot be relabeled REFERENCE or DATA_RICH by repeating examples. No automatic developer/tool SFT, sparse mechanism, promotion or source redistribution.

## CORPUS-1: rights-tracked local release

Source-of-truth is a new `corpora/devmind-v1/` project using v2 source/release declarations and the prospective [rights protocol](../../../docs/rights-policy.md). Pin exact Git commits, source license URLs, SPDX expressions, notices and training restrictions; screen every *selected* file path and nested machine-readable rights evidence. Known GPL/copyleft and Apache/MIT terms can be eligible with their obligations; exclude review-required, vendor, third-party, bundled/generated, ambiguous or sensitive content. Record by-file SHA, root terms versus exceptions, exclusion reason, source URI/revision and publication mode `metadata_reconstruction_only`. Source-backed bytes and training export stay private. The rejected OpenStax bundle and all v0 experiments are unchanged. Selection prioritizes developer/systems relevance and first-party code/docs over gross volume. A deliberate absence of general textbook prose is not filled with unrelated data.

Declare source-family-disjoint train/validation/test assignments; generated worlds/templates never cross splits. Keep frozen v0 cards as 96-source-parent/100-world PILOT diagnostics if independent for the new release, but do **not** silently relabel their parent release. Rebuild or independently freeze new cases when source IDs, content, worlds or partitions change. Stronger MODEL-1/promotion needs ≥200 truly independent test cases per gated capability and separate controls. Re-audit exact and bounded lexical near-duplicates; inspect/repartition the seven prior Kubernetes candidate file pairs, not merely turn off warnings. A passed bounded lexical scan does not prove semantic disjointness. CORPUS-1 requires verified acquire/build/freeze, rights inventory and local audit; one unresolved required source or heldout family blocks its inclusion, not necessarily the entire narrow pilot if remaining coverage is honestly reported.

## TOKENIZER-1: disjoint probes and frozen fit

Freeze separately authored versioned probes for prose, Python, Go, Rust, shell, YAML, JSON, TOML and logs **before fitting**. Owned deterministic synthetic log syntax is valid *only* as a tokenizer probe, not factual corpus, heldout source evidence or a shortcut to nine train/validation source groups. Probe IDs/text hashes must not appear in tokenizer fit document IDs/hashes. On a rights-eligible CORPUS-1 release, run the existing 16,384/24,576/32,768 ByteLevel BPE bakeoff using one train-only fit sample and one family-disjoint validation selection, selecting the smallest vocabulary with heldout bytes/token at least 98% of best. Keep all candidate manifests, identical fit/validation receipt, per-kind real-source compression where observed, independent probe results, vocab-cost (`selected_vocab_size × embedding_width`), selected tokenizer JSON/manifest and SHA. If the strict bakeoff cannot assemble its required real train/validation kinds, report the exact absent kinds; never leak probes into fitting to bypass this gate.

The historical schema-v1 bakeoff and its nine-real-kind failure remain unchanged.
For this pilot a new schema-v2 declaration uses **all** groups actually present
in both independent train and validation source families, with the same
candidates, byte cap and 98% decision rule. Groups without paired real source
documents are reported as unmeasured source coverage; their independently
authored probes supply syntax diagnostics, never fit examples or evidence of
real-world breadth. An omitted measurable group is an error.


Count distinct retained **train normalized source** tokens by content hash once, separately from source-transformed, deterministic synthetic and other-generated selected train-view tokens. Also report full planned target exposures; none of the latter counts as distinct source supply. Measure the actual broad-language share; source family and origin remain separate denominators. Label the observed corpus **PILOT** when it supports only bounded debugging/early behavior, **REFERENCE** only with independent-source breadth and measured train supply commensurate with the chosen model/budget, and **DATA_RICH** only after at least 150M distinct eligible source tokens plus diversity/rights/heldout gates. These labels describe measured supply, not model quality.

## MODEL-0: conditional single dense control

Choose and preregister architecture and target budget **after** tokenizer/eligible-source measurement. Low PILOT supply calls for an inspected ~30–50M total-parameter dense PyTorch model and a short explicitly bounded exposure budget, not the unmeasured 90–120M proposal; materially greater independent supply and measured runtime can justify the larger size in a separately reviewed config. Dense attention/FFN, tied embeddings, no Engram/MoE/MLA/sparse attention; single seed-42 fresh `ExperimentPlan` cell with typed pinned Corpus Forge release/export, selected tokenizer, independent pilot cards, explicit checkpoint retention and no fabricated comparison. `experiment validate`, `inspect`, `prepare`, `lock` and local `sparselab inspect`/stage smoke/warmup must all pass. Do not use bespoke training scripts.

Before accelerator dispatch, from the **already provisioned** worker run `uv run --locked --no-sync` and record `torch.__version__`, `torch.version.hip`, `torch.cuda.is_available()`, count and device name; require the expected RX 7900 XTX and a numerical BF16 staging pass. Do not sync/replace vendor Torch. Verify stage throughput, peak VRAM, workspace bytes/inodes and safe full-state checkpoint growth with ≥25% margin; record tested clean code/lock identity, effective config and no concurrent physical-device job. If ROCm is unavailable, finish reachable CPU validation/inspect but stop without a CPU substitute. If training starts, collect/verify the terminal checkpoint, heldout LM, pilot technical comprehension/source QA/unknown/causal/state cards, independent regression/sampled prompts, triage and bounded continuation/source overlap diagnostics. Pilot scores and one model checkpoint are descriptive; developer SFT requires a **separate reviewed** decision and stronger ≥200-case promotion evidence.
