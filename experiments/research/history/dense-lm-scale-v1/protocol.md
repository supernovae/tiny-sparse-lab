## Scientific question and fixed conditions

Does the previously piloted ~50M *dense* decoder change held-out learning or individually inspected fixed-prompt behavior relative to the mature ~30M dense reference at exactly 16,384 updates / 16,777,216 supervised target exposures? The reference is the three seed-matched [token-budget terminal checkpoints](../../../artifacts/acceptance/dense_lm_token_budget_v1.json), **not** a promoted replacement for `dense-lm-v1`. One intervention: model hidden dimension 512→704, layers 8→10, FFN 1,408→1,168; heads remain 8, maximum model context 256. Both are fully dense; no architecture novelty. Count and record actual total/trainable/active-per-token parameters using `sparselab inspect`; prior pilot reports 29,893,120 versus 50,274,752 total. Changing several dense dimensions identifies a *combined capacity effect*, not the independent effect of width, depth, or FFN expansion (the absolute FFN dimension actually decreases).

Use [configs for seeds 42](../../../configs/dense_lm_scale_v1_seed42.yaml), [17](../../../configs/dense_lm_scale_v1_seed17.yaml), and [73](../../../configs/dense_lm_scale_v1_seed73.yaml). Hold TinyStories source/revision, train-only tokenizer bytes, packed train/validation arrays and supervision masks, data limits, target-token budget, sequence length 128, effective batch 8 (microbatch 8 × accumulation 1), gradient clipping, AdamW betas/decay/warmup/cosine-to-floor-at-4,096-then-floor schedule, FP32, PyTorch ROCm device 0, deterministic seed values, validation 64 batches / 65,408 held-out targets every 200 steps, and six [frozen prompts](../../../data/dense_lm_v1_prompts.json) with the same 32-token greedy decoder and evaluator. Independent random model initialization differs by architecture; this is not a parameter-matched initialization or a new independent test set. The small run is a full-state 4,096→16,384 continuation, the large run starts fresh with exactly the same LR per update and the same packed-data order by seed/epoch. Verify input digests in effective manifests; do not silently accept identity, backend, schedule, or precision drift.

Compare initial (step 0), 200, 400, 1,024, 2,048, 3,072, 4,096, 8,192, and 16,384 step losses where available and the 200-step periodic trajectories, not only the endpoint. Exercise the immutable large-model generations at 4,096, 8,192, and 16,384 if retained; terminal 16,384 against each seed's small-model terminal panel is primary. Keep original six case names and raw outputs; report nonempty/boundary/repeatable checks, repeated-token/bigram/trigram excess, entity and color/object drift, and unusual OOD output separately without a pooled prose score or adjusting decoding. A lower loss alone is not better text.

## Execution and staged decisions

Before training, inspect the effective config and architecture/parameter counts and memory estimate; use a task-owned `sparselab-work/experiments/dense-lm-scale-v1/` store. Check free bytes and inodes, stage on the actual ROCm backend through smoke/warmup, measure steady post-warmup targets/sec, peak allocated/reserved VRAM and fit headroom, and forecast update time plus validation/checkpoint/reporting overhead separately. Do not change effective batch, sequence length, schedule, or precision to optimize utilization. If ROCm is unavailable or memory headroom inadequate, preserve evidence and stop rather than substituting CPU. The original 50M pilot's 24 warmed updates measured 9,126.81 targets/s and 1,530,920,960 bytes reserved, approximately 6% of 25,708,240,896 total VRAM; these are *historical*, not acceptance for the new run.

Run seed 42 first with separate immutable generations at declared steps. If its checkpoint/input integrity fails, held-out loss is nonfinite, or terminal loss does not decrease at least 0.05 nats/target from step 0, stop and record the negative outcome. Otherwise inspect its six frozen outputs and compute matched losses, even when they disagree. Replicate *both* seeds 17 and 73 at 16,384 to distinguish a stable no-effect from a seed-specific capacity effect; use the same frozen config family and panel, not a favorable-seed selection. If seed 42 has a difference of ≥0.05 nats/target versus its small-model terminal, explicit correction/regression of a prompt contradiction, or ≥5 change in repeated-token excess for two in-domain cases, this is a material descriptive trigger; replication is still required when none occurs to establish whether apparent no-effect is stable. Record all three results, including negative or interrupted runs, before interpretation. Never extend to 32M here.

Separate LM learning (trajectory and terminal held-out loss); panel behaviors (simple, named character, color/object, temporal/causal, ordinary completion, odd OOD); efficiency (parameter counts, optimizer seconds and targets/sec, whole training command wall, validation/checkpoint/exercise overhead, peak allocated/reserved bytes, overflow/retries and unavailable readings). Produce a parent-regression view: LM learning PRESERVED/IMPROVED/REGRESSED/UNKNOWN (describe evidence), mechanical generation PRESERVED/REGRESSED, fixed cases individually, runtime MEASURED, memory MEASURED, and efficiency as tradeoff, not a winner. No automatic promotion of either 16.78M model. Improved loss and visible behavior suggests a capacity limiter and needs replication before architecture substitution; loss only suggests separate generation/data evaluation; no meaningful loss/behavior gain argues for a different resource-allocation question; worse learning requires optimization/budget checks *without hiding the negative result*. These are interpretations under this data/device/budget, not causal decomposition or general language quality.

Freeze this protocol, three configs, panel and parent identities in `preregistration.md` **before** any new training. Store mutable runs, stage output and exercises under the named work directory and durable evidence references plus results here. `dense-lm-generation-degeneration-v1` is a separate proposed decoding/seed/milestone study; do not change decoding for this scale comparison. No Engram, MLA, MoE or sparse attention in this study.
