# DevMind v2 expanded corpus protocol

**Identity:** `devmind-expanded-prospective-v1`, 2026-09-29. Source declarations live in [`corpora/devmind-v2/`](../../../corpora/devmind-v2/); upstream evidence and excluded alternatives are in the [web/academic](source-map-web-academic.md) and [engineering](source-map-engineering.md) maps. This is a new corpus candidate, not a revision of frozen v0/v1 releases. No final tokenizer or training run belongs to this acquisition phase.

## Training-use decision (private research only)

Include pinned, public, attributable source text when the documented access and source terms contain **no explicit incompatible ML-training prohibition**. An unrecognized SPDX label is not an explicit no-training term. Record site/dataset/publisher terms, license and attribution/notice obligations separately from the training-use decision. Stop for explicit no-ML clauses or required ungranted approval, gated-access bypass, unknowable origin, private/confidential material, secrets, personal/private fixtures, or irreconcilable evidence. Never interpret an aggregator's ODC-By as a sublicense of original web pages or articles. The v3 declarations record `explicit_training_restriction`; the release records `training_use_policy: allowed_unless_explicitly_prohibited`. A restricted, incompatible or unknown training status is not selected. Eligibility for private research is **not** approval to redistribute source text, train commercially, publish model weights, or claim general-purpose deployment rights. Public output is metadata and reconstruction references only; original source terms remain attached to local snapshots.

## Frozen selection, exclusion, and evaluation rules

- Exact HF repository commit + one named input shard + upstream SHA-256, bounded compressed/shard bytes, row prefix, deterministic revision/path/row-index hash modulus, output row/byte caps. Native Git selections pin the commit and explicit first-party paths. Direct Wikimedia dump selections bind the completed dump date and official SHA-1; the adapter also records the locally measured compressed SHA-256. If a cap is hit, fail and record the failure; never silently add different shards or swap an upstream snapshot.
- Priority for a mirrored item: primary first-party page or paper > credited dataset derivative > generic crawl. Preserve all duplicate-origin attribution in the file/row receipts and audit, but count normalized identical training text once. An exact train/held-out overlap removes the train copy; validation↔test overlap is an error. Cross-source URL, paper ID, and near-duplicate findings are candidate review signals: lexical MinHash is not proof of no semantic contamination. Do not count gross compressed bytes or another publisher's tokenizer total as DevMind source tokens.
- Whole source families in [`splits.yaml`](../../../corpora/devmind-v2/splits.yaml): FineWeb, peS2o abstract and full-text shards, OpenWebMath, Wikipedia, official Go FAQ, Go, Python, Rust, Linux, Kubernetes, OTel Collector and specification, and the small public OMP `harness_contract` control train; Wikibooks, Git, PostgreSQL, and OCI runtime specification validation; Prometheus test. The bounded peS2o first shard was measured as 254,985 selected `s2ag/train` abstracts (336,617,208 raw text characters), **not** full papers; the distinct 7,089,800,772-byte pinned last shard supplies candidate `s2orc` full texts subject to record verification and screening. A train shard mixing Common Crawl `dump` and URL hosts is **not** itself a validated source-family holdout. Before a final tokenizer fit or downstream claim, group row-level crawl/host/paper families, reserve disjoint validation/test families, and screen direct/crawl mirrors of each reserved family. Existing v0/v1 samples and benchmarks are not silently treated as an independent sealed v2 test.
- Evaluation exclusion registry, frozen for this candidate: all `v2_prometheus_promql_test` raw paths/contents/close mirrors; `wikibooks_20260901`, `v2_git_technical_validation`, `v2_postgres_backend_validation` and `v2_oci_runtime_specification_validation` are independent validation families and not train material. Wikipedia and Wikibooks page IDs/book roots are retained; a whole dump being one split is not proof that crawl mirrors of those pages are absent. Exclude benchmark solutions, public test prompts/answers, training-process logs, issue/fixture secrets and low-confidence near duplicates; preserve rejected provenance rather than relabel it as eligible. First-party Go FAQ is authored small Q&A-shaped documentation, **not** volunteer community Q&A. The small published OMP behavioral reference is a documented train-side control, never a sealed evaluation target.
- Row screening rejects obvious private keys, access tokens, SSN-shaped identifiers, high-confidence credential assignments, empty/short crawl records, missing web URL provenance, and Stack Exchange/Reddit/Pastebin mirrors. File selection excludes third-party/vendor/generated/test fixtures. Unknown or explicitly restricted candidates stay in the exclusion ledger, not under a permissive dataset-level license. Inspect actual per-source counts and audits before any readiness label.

## Scale and hard gates

Preferred supply is at least **500 million distinct eligible normalized source tokens**, with 1 billion better, before a later tokenizer-fitting decision. This protocol intentionally does **not** fit a tokenizer now; exact DevMind tokenizer tokens cannot exist until an immutable tokenizer is selected and applied to the deduplicated train text. Report exact fetched/compressed and normalized bytes, row/document/duplicate/drop counts, split and domain/rights distributions, disk use and an explicitly labeled tokenizer-independent approximation. A corpus is `CORPUS_EXPANDED_READY_FOR_TOKENIZER` only after those measurements, evidence records, evaluation isolation review, and separate source-rights/weight-publication decisions have been documented. A larger but unmeasured or rights-mislabeled raw cache is not a ready corpus.

Blocked/deferred sources under this protocol include Stack Exchange dumps, APIs and mirrored posts under the current [acceptable use policy](https://stackoverflow.com/legal/acceptable-use-policy) barring automated gathering for LLM training without written consent; gated The Stack v2 content; the no-content Stack-Edu blob index; Terraform BSL 1.1 root; unlicensed/arXiv-default full text; and general RFC prose pending stream-specific rights review. Their volume never counts toward the denominator. No rejected or interrupted acquisition is deleted to manufacture a success claim.

## OOM recovery and bounded-memory gate (2026-09-29)

The first offline build was kernel-killed while processing `sparselab-work/experiments/devmind-pretrain-v2`: ~31.5 GiB anonymous RSS after ~7 minutes. The verified 19-source acquisition snapshots remain intact; the 710,034-row `.build-dsrznom8` directory is **interrupted staging, not a release**. The cause was full-source JSONL materialization plus several simultaneous in-memory document, dedupe, view and verification inventories, not a demonstrated leak or worker-pool fanout. Preserve that staging for forensic comparison; never freeze or resume from it.

Failed and recovered command: `uv run --locked sparselab --work-dir sparselab-work/experiments/devmind-pretrain-v2 corpus build corpora/devmind-v2/corpus.yaml --offline`. The later `corpus freeze <immutable-build-path>` verified the new build and emitted the release identity listed below.

The v3 LM-only build now reads one HF/Wikimedia JSONL record at a time, normalizes to verified content-addressed per-file receipts, indexes full text and exact/canonical origins on the workspace filesystem with SQLite, and streams sorted immutable outputs, rights and measurement records. Re-entry verifies source snapshot identities and each completed shard's file sizes and SHA-256; an incomplete or conflicting shard is not silently reused. `corpora/devmind-v2/progress/<build-id>.jsonl` is an append-only attempt journal (phase, input bytes, record counts, elapsed/rate/ETA, RSS/peak RSS and available system memory); it is **not** a scientific artifact or part of the build identity. The separate lexical near-duplicate audit still fails closed on declared document/text/shingle caps and is not proof of complete semantic independence if it cannot screen this corpus.

In isolated synthetic FineWeb-style row-prefix benchmarks (2,000 / 4,000 / 8,000 / 16,000 rows, ~9.9 kB per input row), measured process peak RSS was **280.3 / 281.1 / 283.2 / 286.4 MB** while input bytes grew **19.8 / 39.6 / 79.2 / 158.4 MB** and SQLite index size grew **26.7 / 53.5 / 106.9 / 213.8 MB**. This tests source preparation plus exact/canonical SQLite dedup only; it does not establish full-build memory, release validity, model quality, or tokenizer-scale suitability. A separate tiny v3 build/freeze verifies the complete path and compares immutable LM source/view hashes against the legacy builder. Before a full restart, require focused regressions and a committed, pushed code revision. Preserve the failed stage and verified snapshots.

Environment observed at the failure/recovery boundary: WSL2 Linux x64, ~31 GiB RAM, 8 GiB swap free after the kill, no effective per-process virtual-memory limit or memory cgroup; the active `uv run --locked` environment is the project's `.venv`. Optionally increase WSL `.wslconfig` memory/swap headroom and restart WSL as a **safeguard**, not a substitute for bounding corpus retention. Record actual RSS and disk capacity before and during the resumed build. Do not fit a tokenizer or launch training in this phase.

The resumed full build processed 710,034 normalized documents in 389.716 seconds and observed **1,234,657,280 bytes process peak RSS**, versus ~31.5 GiB anonymous RSS at the previous kernel kill. This is execution evidence for this workload, not a portable memory bound.

Acquisition receipts bind 19 snapshots.
