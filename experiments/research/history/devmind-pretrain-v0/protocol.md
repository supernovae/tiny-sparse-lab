# DevMind pretrain v0 — staged preregistration

## Question and invariant

Can a 90–120M **total** parameter dense PyTorch decoder trained on licensed, pinned Corpus Forge source become a useful developer/systems control at 201,326,592 supervised target exposures? This is a **single-control** observation, not a sparse-architecture comparison or a claim that an experiment completed. No Engram, MoE, MLA, or sparse attention. Freeze A (rights, source, splits, release, evaluation cases) before B (tokenizer choice), then C (plan/lock and runtime gates), then D (base review). E and F are separate, conditional scientific plans, not extra phases silently added to the control. No direct bespoke training script.

## A: source and independent evaluation

The [corpus project](../../../corpora/devmind-v0/README.md) records exact Git revisions, selectors, terms, origin, split, and deterministic scenario versions. Git documents follow disjoint source families. World seeds 0–799 are train, 800–899 validation and 900–999 test per generator, with separate template families in each split. The sealed card/test population must use only test-assigned documents/worlds/templates; tokenizer fitting and selection may use train/validation only. Verify normalized-content and parent/near-duplicate leakage before opening any model outcome. Keep the source/license/exclusion receipt and static corpus audit under this directory; immutable bytes and build output stay ignored in the named workspace. The 200-case-per-objective gate cannot be satisfied by 100 unique test worlds per generator **unless independent held-out document cases supply distinct families**; mark those groups underpowered and disallow E/F promotion rather than duplicating cases.

Freeze separate objective exact-answer cards for technical comprehension, cited source QA, missing-source abstention, state tracking, causal troubleshooting, next diagnostic, operational risk, verification, code/config understanding, inert tool-call protocol, and stopping after verified success. Include unauthorized/out-of-workspace destructive requests, conflicting or stale source, contradictory tool output and missing rollback as negative cases. Answers are concise observable `goal/evidence/constraints/risk/next diagnostic/action/verification/rollback/unknowns`, **not hidden reasoning**. No fabricated score for sampled prose: retain regression generations, sampled generations, triage and Surface Review as diagnostics. For each independent card report n, matched random/initial controls, exact accuracy and paired bootstrap 95% interval (10,000 seeded resamples; seed 42); no pooled capability score. The full-answer exact scorer cannot score free-form explanations as objective truth; use a bounded four-choice/exact structured outcome or label it qualitative. If a population is <200 independent cases, report its denominator and underpowered status and do not use it as a promotion gate.

## B: tokenizer and distinct-content gate

ByteLevel BPE 16,384/24,576/32,768 on the same train-only, hash-ordered and per-kind-bounded sample; same held-out validation IDs for each candidate. Record compression per prose/Python/Go/Rust/shell/YAML/JSON/TOML/log kind, document token p50/p95/p99/max, rare-token utilization and tied embedding parameters. Choose the smallest vocabulary within 2% of the maximum train-byte-weighted held-out bytes/token. Keep complete tokenizer provenance and SHA; `corpus describe --tokenizer` counts actual selected LM/chat views and measured general share. Deduplicate normalized train content hashes before evaluating the ≥150M **distinct eligible train tokens** gate; copies of a passage cannot fill this requirement. Missing real modalities, rights, source diversity or tokens means finish A/B and stop before C, recording the gap and a newly reviewed source proposal.

## C: conditional single dense control

One fresh seed-42 `pretrain:single` cell, no comparisons. Proposed architecture: hidden 768, 12 layers/heads, FFN 2048, tied embeddings, dense attention and FFN, max context 2048; inspect actual 90–120M parameter inventory. Proposed training: seq 1024, microbatch 1, accumulation 8 (8192 targets/update), 24,576 updates / 201,326,592 targets, AdamW 3e-4→3e-5, 2,048 warmup, weight decay .1, betas (.9,.95), clip norm 1, seed 42. Validation every 512 updates, durable checkpoints every 3072, retain best/previous/terminal and eight periodic milestones. Report preparation, update, validation, checkpoint and evaluation timings separately. Use BF16 only after actual provisioned ROCm worker/HIP/numerical staging; FP32 or seq512/accum16 requires a new reviewed plan and lock. No local WSL2 hardware inference or CPU stand-in. Storage estimate uses observed full-state checkpoint size ×12 plus caches and 25% headroom with free inode gate. Pilot locked cancel→verified full-state child resume before long training. Freeze exact source/config/tokenizer/code commit and clean separate runner checkout; incrementally push the tested feature branch and do not edit running checkout.

## D: base decision and conditional descendants

Verify full-state terminal checkpoint, held-out LM and 11 disjoint capability outcomes, generator regression, sampled outputs, source/shape/token and license mix, runtime/memory, end-of-budget learning state and triage. **Promote only** if complete verified checkpoint, improving held-out LM loss from initialization, ≥10 absolute point gains on *each* independent technical-comprehension and cited-source-QA card relative to matched random/initial controls, no unstable updates, and adequate card case counts. Otherwise preserve negative/failed/censored Finding; no E/F run. Base not knowing chat delimiters is not by itself a base-model rejection. E, if accepted, must separately pin parent and tokenizer and verify assistant-only acquisition without >10% relative LM loss increase or >5-point comprehension regression; F is gated by useful E and must retain E outcomes. Neither a triage score nor a qualitative prose impression overrides a sealed gate. Hold all criteria fixed after viewing final outcomes.
