# DevMind v2 engineering source map — proposal, not acquisition

**Status (2026-09-29):** upstream/source-policy research only. No v2 source has been acquired, declared eligible, normalized, deduplicated, tokenized, or trained here. Root licenses and example paths below are evidence of *possible* selections, not a blanket per-file license grant. Prospective private-training suitability, permission to redistribute raw excerpts, and permission to publish weights are separate decisions; preserve the license/attribution/notice/changes ledger for each selected path. A known public source with no explicit incompatible training prohibition can be proposed without a per-file human legal attestation, but unknown provenance, explicit no-ML restrictions, private secrets and gated access fail closed. Preserve v0/v1 releases and their failed gates; use a new versioned declaration if selected.

## Bulk code indexes and community Q&A: separate access from content rights

- [Stack-Edu](https://huggingface.co/datasets/HuggingFaceTB/stack-edu) [dataset revision `eeec5caac5cc3758a18f1d3ba4416837a9ba814c`](https://huggingface.co/datasets/HuggingFaceTB/stack-edu/tree/eeec5caac5cc3758a18f1d3ba4416837a9ba814c): the [dataset schema/card](https://huggingface.co/datasets/HuggingFaceTB/stack-edu/blob/eeec5caac5cc3758a18f1d3ba4416837a9ba814c/README.md) exposes `blob_id`, language, `repo_name`, `path`, encoding, `length_bytes`, score, detected licenses and `license_type`; **not a source-code `content` column**. Its 125B-token statistic belongs to the creators' SmolLM2-tokenizer dataset, not this project. The dataset endpoint reported `gated: false` at inspection, but the linked upstream [Stack v2 full-ids](https://huggingface.co/datasets/bigcode/the-stack-v2-train-full-ids) reports **gated**, and its raw README returned HTTP 401 here: do not bypass agreement or assume the index confers content/redistribution rights. Detected-license labels, especially `no_license`, are screening hints, not per-blob authorization. Duplicate forks and absent repo revision/path license binding make unrestricted index ingestion inappropriate; if considered later, restrict to independently pinned reviewed repos and resolve every content hash to the matching upstream path/revision, then deduplicate by content and repository family. Its SWHIDs/blob hashes alone cannot prove provenance of a particular file version.
- [Software Heritage's access documentation](https://docs.softwareheritage.org/user/using_data/) distinguishes non-bulk REST API, graph/ORC exports **without file content**, and public `s3://softwareheritage/content/<sha1>` content objects. It cautions on takedowns, archival lag and personal data; [SWH content policy](https://www.softwareheritage.org/legal/content-policy/) explicitly says the archive does **not vet** its holdings. Public bytes are not a license; verify `sha1` versus Git `sha1_git`, repository/revision provenance, terms, notices, secret/privacy screen. Do not confuse gated graph/API/bulk dataset access with permission to fetch billions of blobs, evade rate limits, or convert no-license files to usable data.
- [Official Stack Exchange dump notice and amended acknowledgment](https://meta.stackexchange.com/questions/401324/announcing-a-change-to-the-data-dump-process): quarterly per-site profile downloads replaced official archive.org uploads; the acknowledgment says files are for one's own use/projects **not including LLM training**, with a separate contact/partner route for LLM training. Therefore **exclude contemporary account-downloaded dumps for this project absent approved training-specific access** despite posts' CC BY-SA terms. [2024 dump update](https://meta.stackexchange.com/questions/402501) records per-site `.7z` `license.txt`, schema snapshot and published SHA256s; none constitutes training permission. Archive.org mirrors and third-party Q&A exports are not a loophole or a verified current official provenance source. [Post licensing](https://stackoverflow.com/help/licensing) depends on revision dates (CC BY-SA 2.5 before 2011-04-08, 3.0 through 2018-05-01, 4.0 thereafter); credit each contributor/post/revision URL and mark modifications if an authorized source is obtained. The [official API agreement](https://stackoverflow.com/legal/api-terms-of-use) binds API access to Terms and attribution; the API is not a bulk-dump substitution and must not be used for prohibited scraping. Do not budget Stack Overflow/Server Fault/Unix & Linux/DBA/Security Q&A tokens until a compliant access route, per-revision license and privacy filtering exist.

## Systems standards and native OMP control

- [RFC Editor reuse summary](https://www.rfc-editor.org/series/rfc-use/) and [IETF Trust TLP 5 §§2–4, 8](https://trustee.ietf.org/documents/trust-legal-provisions/tlp-5/): whole RFC prose can be copied/distributed unchanged with notices, but **modifying** document text outside the standards process is not generally licensed; pre-2015/other streams differ; specified code components may have Revised BSD terms. Bulk normalized/modified RFC prose or generated QA from it is therefore **reference_only pending document-specific review/permission**, not automatic training corpus. For an independently reviewed code-component candidate, bind RFC number, publication date/stream, exact code boundaries and legend; exclude patent/embedded third-party uncertainties. [W3C's 2023 software/document license](https://www.w3.org/copyright/software-license-2023/) permits copying/modifying/distributing covered works with full notice, prior notices and change notice, but check the license notice **on each specific technical recommendation** before considering it; no standards text has been measured/acquired here.
- **Tiny `harness_contract` source family (not a volume source):** the local OMP [MIT LICENSE](../../../LICENSE) applies to authored code/documentation; pin the actual Git commit when declared (worktree HEAD observed `7b5339ecd91852f6df14f41705b960da1f5542cc`, not an OMP upstream URL). Candidate authored paths: [AGENTS.md](../../../AGENTS.md) §§Start safely/Workspaces/Experiments and [README.md](../../../README.md) §§What is implemented/Corpus Forge. Map `harness_contract` to observable constraints: safe authorization and workspace scope, no implicit tool execution, inert versioned tool transcripts, artifact identity and immutable checkpoint/resume, source rights versus release rights. Treat these as descriptions of **SparseLab** behavior, not transferable live-tool permissions or model instructions. Keep family disjoint from its own evaluation prompts; exclude generated artifacts, `.venv`, fixtures/secrets, run transcripts and text quoting other sources without vetted rights. Size is small/unmeasured; do not pad a token target by duplicating it.

## Scale and independence protocol for a future declaration

- The measured raw candidate trees above already include roughly hundreds of MB of code+docs across multiple programming/systems verticals; Linux `drivers/` alone is >1 GB raw but specifically excluded. **Inference:** after auditing, selected first-party code, docs and a legitimately accessed Q&A component *could* plausibly offer tens of millions of source tokens; hundreds of millions require much wider independently rights-reviewed repositories or authorized large-scale access. No tokenizer was fit, no selected eligible byte inventory exists, and no measured 10M/100M/150M distinct-token supply or Q&A volume can be claimed from gross bytes. Stack-Edu's creator-reported 125B tokens and upstream content-ID index are not DevMind measured supply. Report later the cascade: tree blobs/bytes → accepted text bytes → normalized content hashes → deduplicated eligible train bytes → selected-tokenizer unique tokens; exclude heldout bytes, generated views and duplicated forks at every appropriate step.
- Group by **repository + upstream document/package/topic + language**, not random rows. Proposal: train CPython `Doc/library` and selected `Lib` packages, Go `doc`/selected `src` packages, Kubernetes concepts, audited Linux `fs/` and selected kernel docs, PostgreSQL owned SQL/storage sources, OTel owned implementation; validation distinct CPython `Doc/tutorial`/`Lib/asyncio`, Go `src/net/url`, Kubernetes tasks, PostgreSQL separate chapters/packages, Envoy implementation if cleared; test **independently held-out** Kubernetes tutorials, selected Rust compiler families distinct from Rust Book, Prometheus PromQL/TSDB families, Linux `net/` subfamilies and independently selected PostgreSQL chapters (only once actual family inventories support all three splits). These are *proposed*, not verified sufficient or rights-cleared. If retaining v0, keep every v0-selected parent and near duplicate out of future test, including known [seven Kubernetes cross-split overlaps](../devmind-pretrain-v1/source-survey.md#independent-evaluation-and-near-duplicates); otherwise rebuild the new corpus without mixing old v0 views. Deduplicate across forks, copied docs, versions, same examples in prose/tests, and derivatives by exact content hash plus lexical near-duplicate review. Reserve separately sourced evaluation cases by whole repo/topic/version and hold out source pages, code package families, prompt templates and synthetic worlds together. Source-Q&A pairs from licensed material retain cited parents and revision; do not call neighboring paraphrases independent evidence.
- Before any actual v2 declaration: pin verified selectors/SHAs and per-path provenance, exclusion and notices; screen explicit no-ML/terms, secret/private fixtures, personal data and unknown-license content; determine training-use status separately from `redistributable` versus `metadata_reconstruction_only` and weight-release review; obtain Q&A access only on compliant terms; count after source-parent/near-duplicate splits. Stop rather than turn provisional registry rows into acquisition receipts.
