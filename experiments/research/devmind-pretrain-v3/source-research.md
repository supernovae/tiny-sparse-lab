# DevMind v3: standards, manuals, and code-index research

**Decision date: 2026-09-29. Research only.** This is not an acquisition, permission certificate, token count, tokenizer fit, or model-training result. The controlling [v2 protocol](../devmind-pretrain-v2/protocol.md), [engineering map](../devmind-pretrain-v2/source-map-engineering.md), [`corpora/devmind-v2/corpus.yaml`](../../../corpora/devmind-v2/corpus.yaml), and [release policy](../../../corpora/devmind-v2/release.yaml) define the baseline. The private-use rule is `allowed_unless_explicitly_prohibited`, **not** a claim that public access licenses every use: inspect access conditions, original authorship, file-specific rights and notices; exclude explicit incompatible restrictions, unclear origin, secrets, and private material. Source text publication and model-weight licensing require separate review. This research does not alter immutable v2 snapshots.

The v3 project currently carries v2's 19 declaration files as an unchanged baseline; none of their already-selected bytes becomes a new v3 developer source by relabeling it. These bounded standards candidates are deliberately **small**. No selected-byte inventory was measured and no credible claim of tens of megabytes per standards repository, 500 MB unique developer text, or a 30% developer mixture follows from them. Reaching a much larger source target requires separately audited first-party implementation/code/test families, not broadening these standards selectors to vendor copies or counting Stack-Edu IDs as content.

**Document-specific additional selections (not Git):** [RFC 8949 original `.txt`](https://www.rfc-editor.org/rfc/rfc8949.txt), December 2020 IETF Standards Track, has its own copyright/TLP legend **without** the pre-5378 restriction legend present in [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.txt). The [RFC Editor's reuse statement](https://www.rfc-editor.org/series/rfc-use/) and [TLP 5 §3(c)](https://trustee.ietf.org/documents/trust-legal-provisions/tlp-5/) allow copying/distributing the **unmodified complete** RFC with legends; neither contains an explicit ML-training ban. Under the project's private research rule, RFC 8949 is an **include-now candidate for the original complete document only** (`v3_rfc8949_train`, `explicit_training_restriction: none_found`, `rights.training_eligibility: eligible_with_obligations`; license should identify IETF Trust TLP, not falsely label all prose `BSD-3-Clause`). Fetch only fixed numbered official `.txt` (not mutable errata page), preserve the complete original plus copyright notices in private provenance, identify original byte hash/size on future acquisition, and publish metadata only. TLP §3(d) does **not** grant modified RFC prose redistribution outside the IETF process: do not publish altered/segmented RFC text, unlicensed synthetic derivatives or RFC code components without their distinct §4 BSD conditions. A legal/process review is still needed before any release beyond private source-backed training; if the actual adapter cannot preserve this boundary, reject rather than treat the complete RFC as generally transformable content. RFC 9110's explicit pre-5378 warning keeps it in **needs review**, not this cohort.

**NIST SP 800-92**, [official final publication and authors](https://csrc.nist.gov/pubs/sp/800/92/final), [versioned PDF](https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-92.pdf), DOI [`10.6028/NIST.SP.800-92`](https://doi.org/10.6028/NIST.SP.800-92): two NIST employee authors, Kent and Souppaya, and inspected report front matter/acknowledgments. The [NIST technical series policy](https://www.nist.gov/open/license#techpubs) grants broad reuse and derivatives for NIST employee works subject to attribution; no explicit ML ban identified. Candidate `v3_nist_log_management_train`, document-specific NIST publication rights rather than an invented SPDX code license, `explicit_training_restriction: none_found`, private training with NIST attribution and changed-text notices. Select only report text, excluding cited third-party excerpts, logos, figures and real identifiers/logs on screening. **PDF URL/DOI names an edition, not a proven immutable byte object**: acquire later only with recorded SHA-256/PDF length and reject future drift; validate the HTTP declaration's revision/checksum semantics and rights-reference representation before promotion. Do not treat external contributions acknowledged in front matter as standalone NIST-authored works.

For Git declarations use `schema_version: 3`, `kind: git`, `canonical_uri` of the first-party `.git`, exact SHA40 revision, `id: v3_*`, separate `source_family: v3_*_train`, and domain/document kind identifiers from existing conventions. Use explicit allowlist paths, **not** `**/*`; exclude `**/vendor/**`, `**/third_party/**`, `**/generated/**`, `**/fixtures/**`, `**/testdata/**`, `**/*secret*`, `**/*private*`, lockfiles/binaries and copied RFC excerpts. A conservative **per-source** `max_bytes: 2000000` for spec/book selections is a ceiling to revisit against measured tree files, not a claimed volume or truncation invitation; fail if exceeded. Set separate bounded PDF/RFC HTTP caps after measuring original bytes. These prose selections intentionally do not collect tests. For implementation repositories outside this set, retain small authored tests only after individual provenance/fixture screening, rather than globally excluding all tests. The current adapter's shallow `git fetch` retrieves whole reachable commit blobs even when selecting one Markdown file: actual network/pack cost is **unmeasured** here and may greatly exceed `max_bytes`. Avoid cloning a large monorepo merely for a tiny spec; compare repository byte/pack receipts before acquisition.

## Explicit exclusion now

- **POSIX / IEEE Std 1003.1-2024, Base Specifications Issue 8:** the [download page](https://pubs.opengroup.org/onlinepubs/9799919799/download/index.html) says archives are **personal use only**; [online terms](https://pubs.opengroup.org/onlinepubs/terms.htm#c950) expressly disallow copying/reprinting/otherwise reusing material without explicit permission from The Open Group/IEEE. Do not use downloaded or mirrored POSIX text as private corpus under a permissive default; seek rights holders' explicit approval before reconsideration. Independently licensed Linux manual pages are not equivalent to a POSIX standards grant.
- **The Stack v2 gated content, Stack Exchange dumps/API/mirrors, and current Terraform BSL root:** remain excluded as in [v2 research](../devmind-pretrain-v2/source-map-engineering.md#bulk-code-indexes-and-community-qa-separate-access-from-content-rights) and [v2 protocol](../devmind-pretrain-v2/protocol.md#scale-and-hard-gates); neither alternate download locations nor dataset wrapper licenses bypass original restrictions. Exclude secrets, fixtures containing real user data, generated/vendor copies, unknown provenance, and benchmark answers everywhere.

## Code-quality indexes: metadata ≠ usable code

- [**Stack-Edu pinned card/schema**](https://huggingface.co/datasets/HuggingFaceTB/stack-edu/blob/eeec5caac5cc3758a18f1d3ba4416837a9ba814c/README.md) has `blob_id`, `repo_name`, `path`, language, `length_bytes`, education `score`, `detected_licenses`, `license_type` and encoding, **not source code content**. Its creator-reported 125B-token figure is unrelated to measured DevMind tokens. Treat as a **bounded quality-selection index**, not a v3 text source or blanket license. [Software Heritage access guidance](https://docs.softwareheritage.org/user/using_data/) distinguishes non-bulk REST, content-free graph/ORC and public S3 `content/<sha1>` bytes; a SWHID `sha1_git` is **not** the S3 content SHA-1. [Archive content policy](https://www.softwareheritage.org/legal/content-policy/) does not vet copyright, privacy, or removals. Public blob availability cannot substitute for origin/revision/file-license verification or bulk access authorization.
- [**The Stack v2 train-smol IDs card**](https://huggingface.co/datasets/bigcode/the-stack-v2-train-smol-ids/blob/main/README.md) is another potential ID-level shortlist, not a grant to materialize gated code. [The Stack Smol card](https://huggingface.co/datasets/bigcode/the-stack-smol) describes a smaller actual code sample but access/terms and individual file licenses must be honored; do not bypass any gate. [StarCoder processed dataset card](https://huggingface.co/datasets/bigcode/starcoderdata/blob/main/README.md) is neither a small independent rights-cleared source nor license for its constituent repositories. [OpenCoder FineWeb code corpus](https://huggingface.co/datasets/OpenCoder-LLM/opc-fineweb-code-corpus) uses web-derived content: an aggregator license label cannot sublicense original web pages. **No dataset bytes admitted or volume counted here.**
- Realistic *future* materialization: if access rights and an index commit/shard/checksum are verified, select at most 1,000 metadata IDs with deterministic `(index revision, language, repository, path, blob-id)` hash ranking, stratify by language/score and cap at 1 MiB per file and 20 MiB retained per source cohort. Require an independently verified first-party origin, exact Git commit/file path, matching content hash and file-level SPDX/notices before fetching code from **that origin**; for any SWH retrieval obey its published mechanism/limits and confirm byte SHA-1 separately. Reject inaccessible, gated, license-unclear, vendored, generated, fixture/private and v2-overlapping paths; dedupe by normalized content and origin, and record rejection counts. This is a proposal, not an assurance that 1,000 eligible files exist or authorization for bulk retrieval. Prefer audited original Git repositories over indirect blob indexes.

## Remaining gates and risk register

1. Verify actual selected file tree, header/NOTICE/SPDX/embedded references and byte sizes at each pinned standards commit; keep tests only if individually first-party and genuinely explanatory. Confirm site terms remain compatible when acquisition occurs. Record per-file attribution, extracted prose transformations and rights in provenance. `none_found` means **no explicit training prohibition identified in inspected evidence**, not universal permission or absence of other restrictions.
2. Before a v3 split, compare normalized hashes, URL/source origins and near passages against all v2 snapshots: **OCI runtime specification, OTel specification, Linux filesystem docs, Git technical validation, PostgreSQL backend validation, Prometheus test**, and overlapping Go/Python/Rust/Kubernetes material. Exclude v2 revision/path copies; exact train/held-out collisions remove train; near mirrors need review, not merely a hash pass. Keep v2 held-out families held out in v3.
3. Resolve NIST authorship, RFC code-component boundaries, Linux page-level terms and stable shell/build/debug source commits before promotion. Document any explicit restrictions and permission correspondence, especially POSIX. Never count unverified candidates toward a 30% developer mixture or a tokenizer gate.
4. Respect SWH takedowns, rate limits, archival lag, personal data, hash-type differences and original source licenses. Frozen index IDs measure a selection *possibility*, not retrievable rights-cleared content. No code acquisition, tokenizer fitting, training, or source manifests were performed for this document.
