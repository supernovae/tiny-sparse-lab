# Proposed hosted qualification resource boundary after C05-I8

**Status: proposal only. Hosted retries are paused.** This replaces the *proposed* resource approach for a future `serving_only=true` qualification; it does not amend the spent C05-I6/C05-I8 contracts, alter the current workflow, or authorize a dispatch. Keep PR #54 draft and the frozen test collection, exact checkout SHA, scientific inputs, persistent model-work ledgers, per-job quotas and failure evidence unchanged. Require an inspected implementation and offline tests before seeking any new hosted allocation.

## Separate provider bootstrap from lab-owned execution

1. **Provider bootstrap:** GitHub creates the runner, checks out the exact requested SHA, installs `uv` through `setup-uv`, and selects Python through `setup-python`. A minimal standard-library preflight after checkout must verify the workflow API head and checked-out commit, read the workflow creation time, and reject an expired 1,800-second deadline before provider setup or model work. A time-only watchdog should remain active during setup, without recursively measuring provider storage. The existing job timeouts remain 5 minutes for lint and 10 minutes for each of fast, macOS archive, Linux serving and macOS serving, totaling 45 runner-minutes. Queue time counts toward the 1,800-second eligibility deadline; a queued job that starts too late must do no model work. Provider setup that fails or overruns stops the job and retains logs.
2. **Lab-owned execution:** Start the fail-closed resource watcher before `uv sync`, budget initialization, test collection, fixtures or model work. Create one empty per-job root under `$RUNNER_TEMP/kml-ci-<job>` and include that entire live tree plus the exact checkout subtree in storage sampling. Count full live bytes and inodes in those two disjoint roots, including the checkout created during bootstrap, logs, SQLite/WAL/SHM files, dependency environment, caches, temporary files, pytest output and reports. A 15-second deadline for a complete sweep remains a failure, with a 15-second shutdown reserve. Never substitute an old sample. The existing 8 GiB process-tree RSS ceiling applies from this phase to the runner worker and all its descendants. Preserve bounded TERM-to-KILL cleanup with proof of zero surviving owned PIDs; a permission or inventory failure produces an unverified cleanup receipt and fails the job.
3. **Confine controllable writes:** C05-I9's `owned_environment` now passes one reviewed environment to every lab-owned command and child. It sets `UV_PROJECT_ENVIRONMENT`, `UV_CACHE_DIR`, `UV_PYTHON_INSTALL_DIR`, `TMPDIR`, `TMP`, `TEMP`, `HOME`, `XDG_CACHE_HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `PYTHONPYCACHEPREFIX`, `PIP_CACHE_DIR`, `HF_HOME`, `TORCH_HOME`, `MPLCONFIGDIR` and `SPARSELAB_WORK_DIR` to subdirectories of the per-job root, plus `UV_PYTHON_DOWNLOADS=never` after `setup-python`. Continue explicit `pytest --basetemp <root>/pytest -p no:cacheprovider`, controlled plugin loading and subprocess inheritance. An offline audit of every selected fixture and helper must identify hard-coded output/cache paths; any unredirectable write needs a separately declared root or removal of that fixture before dispatch. The environment binding is offline-tested, but setting variables alone does not prove confinement.

The pinned Linux C05-I8 jobs exhausted their 15-second sweep within `/opt/hostedtoolcache`. The macOS run observed `setup-uv` placing `uv` under `/Users/runner/hostedtoolcache` and `$HOME/.local/bin`, using `$RUNNER_TEMP` for its archive, and `setup-python` selecting `/Users/runner/hostedtoolcache/Python/3.14.7/arm64`. The runner may also write action logs, checkout metadata, setup action caches and temporary files outside the lab root. These are **provider bootstrap writes**: record versions and paths and observe `statvfs` free bytes/inodes before and after bootstrap, with a proposed fail-before-lab margin of at least 8 GiB free and 100,000 free inodes at the checkout and job-root filesystems. Those observations are capacity safeguards, **not** exact added-byte/inode accounting or proof of a provider storage cap. Do not recursively scan the preinstalled tool cache. If a setup action unexpectedly writes into a supposedly lab-owned root, its contents are counted; if lab execution requires writing elsewhere, stop and revise the declaration before hosted work.

## Limits and changed claim

| Boundary | Proposed enforcement |
| --- | --- |
| Model work | Unchanged non-transferable serving quotas of 20 updates/640 actual targets/113 calls/355 requested generated tokens per Linux and macOS serving job; archive 2/32/0; lint/fast zero; aggregate 42/1,312/226/710. Precharge before work, including child processes; retain failed charges and report actuals separately. |
| Immutable inputs | Exact workflow head and checkout SHA, frozen decoding digest, reviewed collection count/digest and fixture parameters remain fail-closed before model work. |
| Lab-owned memory and storage | 8 GiB process-tree RSS and 4 GiB live bytes/50,000 live inodes per job for the runner descendants and the two declared owned storage roots during lab execution. Root totals are directly sampled; they are not inferred from free-space changes. |
| Time | Existing five job timeouts total at most 45 runner-minutes. The 1,800-second deadline begins at workflow creation, includes queueing, is checked before provider setup and before lab work, and remains watched through shutdown. The proposed time-only bootstrap watchdog needs implementation and an offline expiry test. |
| Provider bootstrap | Exact SHA/deadline checks, setup logs/paths and free-space/inode observations, plus job timeout and time-only watchdog. No 8 GiB RSS or 4 GiB/50,000-inode **accounting claim** for provider setup or preinstalled cache. No paid runner upgrade or automatic retry. |
| Failures | Retain startup, sweep, cleanup, ledger and test receipts. Missing or failed monitoring, escaped required output, cap exceedance, exhausted sampling deadline, cleanup uncertainty or changed fixtures stop before any subsequent phase. |

The old policy sampled checkout plus broad ambient `$RUNNER_TEMP`, `$RUNNER_TOOL_CACHE` and `$HOME/.cache` roots and described the result as whole-job added storage across provider setup. C05-I6 and C05-I8 show that recursively walking the preinstalled tool cache can consume the sweep deadline before lab execution. This proposal narrows **enforced byte/inode coverage** to declared owned roots and begins RSS enforcement with lab execution; provider bootstrap becomes time-bounded and observational for storage and memory. That is a material scope change, not equivalent coverage. No hosted result is qualified by local tests or this document.

Before a future dispatch, implement the workflow/guard phase split, audit fixture paths and setup action writes, test Linux/macOS-shaped path fixtures and deadline/failure receipts offline, and review the changed resource contract. Then request one fresh fixed hosted allocation; do not reuse C05-I8's spent quotas.
