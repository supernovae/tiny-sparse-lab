The component cards report 20.1 GB and 57.4 GB of UTF-8 text across their full releases. Scaling those figures by each selected shard's share of the pinned compressed tree gives a **rough 0.96 GB + 1.28 GB = 2.24 GB expanded-text estimate** if both selected shards were fully materialized. That is a planning estimate, not a measured shard ratio. The proposed native path streams gzip, retains at most 64 MiB of selected rows and removes temporary compressed inputs after verification; it should not write the full 2.24 GB as decoded files. Expect peak additional disk below roughly 1.5 GiB, with the 5 GiB hard cap covering staging, receipts and failures. A code change that retains full shards or writes full decoded text must revise this estimate and cap before any transfer.

## Native transport prerequisite

At the time of S3, the bounded Hugging Face adapter fetched an entire named `.json.gz` shard, streamed a row prefix, checked a declared SHA-256 and limited retained rows/bytes. It **could not execute this exact proposal then**:

1. `HFBoundedShard` validation in `src/sparselab/corpus/project.py` requires config and split markers in the filename. These exact Common Pile names have neither `default` nor `train`, although the dataset metadata reports `default`/`train`. Add a narrow exact-file preflight using the pinned repository tree and dataset config/split metadata; do not mislabel the split to satisfy filename validation. Reject missing or ambiguous metadata.
2. Add an aggregate, durable **transfer ledger** to the existing bounded-shard acquisition path. Bind it to the attempt ID, two source revisions/files and one deadline; reserve the declared full-file size atomically before each source request, charge failed reservations, and refuse a fourth transfer or any reservation exceeding 1,323,415,169 source-body bytes. Bound metadata responses by their separate 1,048,576-byte allowance. Count actual response-body bytes while streaming and stop before either a per-file reservation or the combined 1,324,463,745-byte allowance is crossed. Persist and verify the ledger across process restarts so a retry or resumed command cannot reset it. Disable unaccounted automatic retries and cache fetches. Record actual and charged bytes, attempts, SHA checks, row/output counts and failures in native receipts.

Use the existing native `corpus` acquisition/release and verification commands; do not build a task-specific downloader. The pilot has **no Git input**, so the current Git adapter's post-fetch `max_bytes` is not used as a transport bound. PagerDuty's 36 pinned Markdown files need a separate file-level rights and bounded-transport proposal before any Git/content fetch. Before an approved launch, review the fixed revision and local tests, inspect the effective declaration and output locations, check fresh free bytes/inodes, and record source commit/package identity. Local tests do not stand in for a live preflight or a source-rights decision.

Implementation update, 2026-10-07: [S4](results/2026-10-07-card03-transport-fix.md) records the native code prerequisite in local commits `23db56c` and `c77074e`, with 26 focused and 293 corpus tests passing against local/mock inputs. A budgeted project must declare `transport_budget` in `corpus.yaml` and initialize one ledger with `sparselab corpus budget-init <project>` before `corpus acquire`; each pinned shard declares `declared_config: default`, `declared_split: train`, its exact path, SHA-256 and byte size as `max_shard_bytes`. The ledger binds the attempt ID, sources and limits, charges complete shard reservations before transfer and includes metadata, redirect and error bodies. The table values are now **approved for one attempt and unspent**. The declaration also caps expanded streaming at 2 GiB per shard, separately from transfer, retained-output and disk limits. No live Hub preflight, source-content transfer, rights admission or training has occurred yet.

## Rights and scientific stop rules

- Before raw transfer, review the pinned component cards, Project Gutenberg's [license policy](https://www.gutenberg.org/policy/license) and Wikimedia's applicable [reuse/attribution terms](https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use); document that this is a restricted **rights-review acquisition**, not permission to use all rows for training or redistribution. Stop if source-level terms cannot support that limited review.
- For each selected Project Gutenberg record, preserve ID, title, origin URL, provenance, asserted license and content digest; check the particular edition/work's public-domain or permission basis for the intended jurisdiction, embedded notices, Project Gutenberg trademark/header treatment, and any third-party material. Quarantine missing or conflicting rights evidence.
- For each selected Wikimedia record, keep source wiki/page URL, namespace, revision/date, author/history route, asserted license, imported-text notices and content digest. Admit only individually reviewed English content-namespace pages with a traceable attribution route; quarantine empty/mismatched author metadata, third-party material, talk/user pages and uncertain license terms. Preserve CC BY-SA attribution/share-alike obligations for any later allowed use.
- Record every selected, excluded and unavailable sampled row with reason; do not silently fill quotas. Unscanned and unselected rows remain unreviewed and ineligible. Before any later tokenizer fit or training, freeze source-family splits, cross-source exact/near-duplicate checks and answer exclusions under the Card 03 contract. This pilot produces **no** measured mixture, tokenizer coverage or evaluation score.
- Stop on any cap, source/rights mismatch, checksum failure, missing ledger, unexpected redirect/cache behavior, malformed row, or insufficient storage margin. Preserve negative and partial receipts. A completed download alone does not satisfy Card 03 or Gate 0.

This ingestion-pilot allocation is independent of the later language-training **target-token, optimizer-update and GPU-time budgets**. No training tokens or updates can be borrowed from it. The proposed main architecture stays at **341,885,952 parameters** with vocabulary 32,768, width 1,024, 24 layers, 16 heads and FFN 2,816; no config or checkpoint changes are requested. The native transport prerequisite is complete and accepted for its tested scope; KML-D08 approves one attempt only if its source-level rights and live preflight checks pass.
