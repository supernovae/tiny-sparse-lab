# Integration PR description

This rolling research branch adds the Kernel Memory Lab cards, protocols and retained evidence references from Cards 01–05. Native corpus changes cover bounded acquisition, source-level admission, frozen family splits, train-only tokenizer preparation and a verified token mixture. The scientific record retains failed attempts and the accepted Card 03 release/Gate 0 evidence without treating a negative model result as a reader.

The Card 05 consolidation adds native monitor limits for added workspace use and device-memory identity, persistent common-root baselines, and owned-process shutdown. It extends the existing attempt ledger with a content-bound, cumulative v2 contract for optimizer updates, actual targets, generation calls/tokens and one deadline, including zero-update phases. It adds native receipt-derived counter reconciliation, optional panel decoding controls, exact frozen-item/prompt binding and independently reviewed score inputs for non-promoting readiness decisions. Earlier optional-absent declarations and hashes remain compatible, and the Card 05 scripts and all scientific evidence stay available for comparison.

C05-Q2 supplies narrow CPU/fp32 integration evidence: one explicitly budgeted synthetic fixture completed 3 updates and 77 targets in 32/32/13, with zero generation, cold receipt–ledger agreement and zero surviving owned descendants. Its optimizer-bearing pytest node now skips in ordinary runs and requires an explicit harness context. The previous C05-Q1 attempt failed before its ledger and remains preserved. Card 05's real-data C05-N1 result remains negative at 0/200; this PR does not promote a reader or start Card 06.

Focused offline checks cover legacy identities, monitor and attempt-contract failure paths, frozen suite coverage/prompt substitution, reviewed-score binding and the new opt-in guard. Three historical Kernel Memory Lab records have exact path-and-SHA-256 lint exceptions; changed bytes, alternate paths and extra artifacts fail the linter. Live ROCm qualification, real-panel parity with the tracked scripts and reviewer-independence verification remain open. Main integration and any new runtime are separate decisions.
