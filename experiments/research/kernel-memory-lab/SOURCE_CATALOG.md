## What can start, after admission review?

- Base candidate: a small, version-pinned, rights-audited subset of Common Pile. Resolve source-specific obligations before choosing a mixture. This is distinct from the older Pile or an unrestricted Common Crawl dump
- Domain candidate: Apache-2.0 PagerDuty documentation, with notices and exclusions checked
- Conditional government candidate: individually checked NIST/FAA employee-authored material; federal hosting alone is insufficient
- Behavior candidate: newly authored, rights-cleared cases and simulator-generated observation/action/outcome traces
- Research/read-only initially: Cynefin/Basecamp, Woods, Hollnagel, MIT handbooks, Google SRE, chaos principles, GitHub postmortems, ASRS, current NC OpenStax edition. Loghub is conditional research/academic use, not a default commercial training source
- This classification is an engineering admission policy, not a legal opinion. Unclear rights remain excluded pending permission or qualified review; do not assert that fair use resolves the question

## Synthetic behavior and evaluation plan

Create original CI/CD scenarios in a deterministic, isolated simulator: stale CI status; flaky versus deterministic test failure; canary regression; incompatible schema rollback; retry-induced overload; missing telemetry; network partition; and a simple safe change needing no elaborate process. Use fictional systems and generated data. No employer/customer logs, secrets, paywall bypass, bulk collection, or production actions.

SFT records should contain the visible observations available at each step, concise evidence-backed decision summaries, proposed/allowed actions, test results, recovery checks and final outcomes. Do not treat copied prose, fluent framework terminology or retrospective explanations as expert behavior. Expert-review a small set before expansion; synthetic output is not inherently correct or automatically rights-cleared.

Keep a manifest per item: source URL, author, exact revision/date, content hash, license text/evidence, restrictions, allowed uses, attribution, transformation history, synthetic generator/model terms where applicable, reviewer and split assignment. Quarantine unknown rights and personal data. Preserve licensing separately from the repository’s own code license.

Split by incident family, root scenario, system topology and generator template before generating variants. Keep paraphrases, time slices, translations and counterfactual siblings in one split; deduplicate against base and domain corpora. Reserve unseen failure combinations and independent expert-written cases. Never expose final diagnoses or future observations in earlier turns.

Measure objective behavior: correct next action; unsupported-claim rate; appropriate uncertainty/abstention; information gained per question; evidence that changes the recommendation; safe stop/escalation; bounded blast radius; recovery success and data-integrity invariants; time/action cost; and concise completion on easy tasks. Compare base-only, retrieval-assisted and SFT variants. Penalize both reckless action and needless questions/ceremony. Correct Cynefin vocabulary alone earns no credit.
