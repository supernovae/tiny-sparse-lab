## Noncyclic preparation order

Let `S` be `uv run --locked --no-sync sparselab --work-dir <common-root>`, `P` the unchanged acquisition project, `A` a **new** exclusive attempt root, `H` the original C03-C1 tokenizer/evaluation release, `R` a future candidate release, and `F` its finalized family inventory. Every mutating native leaf below runs as `S attempt run` with its new ledger, the one whole-attempt monitor, the preparation monitor and the owned supervisor. The preparatory zero-counter reservation is still charged as a phase; a failed phase stops. The existing [packet](CARD05_BASE_50M_LAUNCH_PACKET.md#exact-native-operation-map-and-stop-points) specifies the exact `attempt run` flags and original phase limits. This packet replaces its rights/family/release rows and forbids its live acquisition row.

1. **Verify snapshots.** Under the new supervised phase run `S corpus acquire P --offline`, then compare its cold lock/source identities with the table above. No transfer attempt or network metadata probe is permitted. Do not consume B13's working admission/inventory/build files.
2. **Draft and review admission.** Render the application-policy template with only the cold lock and four snapshot digests using `S corpus render-declaration --template <checked-template> --values-json <exact-JSON-map> --output A/prep/application.json`. Run `S corpus admission-draft P --template A/prep/application.json --policy-document <unchanged-policy> --output A/prep/admission-draft.json`. Review the actual draft, automated exceptions and the accepted 8/12/24/24 clear-row spot sample. Keep material/unknown exceptions quarantined; stop a source-wide rights conflict. Publish the exact reviewed v2 admission manifest as a new supervised immutable file via `render-declaration`; publish its adjacent `admission.json.review.json` from `card05-base-50m/admission-review.template.json`, binding the new draft/admission SHA-256, item-level spot audit notes, reviewer and decision. A draft or B13 working copy alone is not accepted. If a row decision must change, stop for a separately reviewed declaration rather than editing a generated draft outside supervision. The native admission verifier must accept the final manifest.
3. **Bind one pre-freeze declaration.** Copy each checked-in source and transform YAML into `A/prep` with the same supervised `render-declaration` command and an empty `{}` binding map; compare its output hash with the checked-in input hash. Render `release-reviewed.template.yaml` with the new reviewed admission path/hash. It has **release schema 2** and `normalizer-structure-v3`; “v3” is the normalizer, not a release schema upgrade. Render `project-pre-freeze-reuse-v2.template.yaml` beside those byte-identical four source YAMLs and transform YAML. Its placeholder split is inert and may be used only by split inventory/freeze. Bind its actual path/hash once with `S attempt bind-artifact --kind pre_freeze_project ...`. Native binding checks the reviewed admission receipt, schema, normalizer and unchanged acquisition digest. The acquisition-only quarantine release must not feed inventory or freeze.
4. **Inventory and reviewed family decisions.** Run `S corpus split-inventory <bound-pre-freeze-project> --output A/prep/split-inventory.jsonl --json`. Inspect exact-content components against the accepted prior family inventory and original held-out release. Publish the reviewed cluster declaration from `card05-base-50m/family-clusters-reviewed.template.json` through the bounded renderer, with exact inventory hash, reviewed merges/seed, source strata and prior family binding as values. Run `S corpus freeze-splits <same-bound-pre-freeze-project> --inventory <inventory> --clusters <reviewed-clusters> --output A/prep/splits-reviewed.yaml --json`. Its native regeneration must match the inventory under the same admission and normalizer. A missing admission, wrong normalizer, changed inventory, incompatible accepted family or shifted held-out assignment stops.
5. **Build from the frozen split.** Render `project-build-reuse-v2.template.yaml` with only the verified frozen split path. Bind it once as `build_project`; native binding requires the same source/acquisition digest, same exact v2 reviewed release and the matching frozen split receipt. Run `S corpus build <bound-build-project> --offline`, then `S corpus freeze <verified-build-root>`. Cold-verify the release. Run the existing `corpus audit` and bounded `corpus near-duplicates`; inspect v3 source spans, cleaning, retained rights, exact/near leakage and each flagged residue. 6. **Accept the exact release before supply.** An independent review records `sparselab-release-review-v1` with `decision: ACCEPTED`, reviewer, exact `R` manifest, `F` SHA-256 and passing protected-lineage receipt. Publish it from `card05-base-50m/release-acceptance.template.json` through `render-declaration`, then bind it once as `release_acceptance`. Native dispatch refuses `measure-tokens`, mixture, prepared-input publication, stage or train before this binding, and refuses a measured/mixture release different from it. The review must also approve the rights/cleaning/leakage audit; a passing CLI exit alone is not acceptance.
7. **Only after acceptance:** measure post-cleaning unique training positions with the unchanged original tokenizer and `--tokenizer-origin-release H`; enforce 20.25M general, 4.50M explanatory and 0.25M incident floors. Render and cold-verify the exact 50M 81/18/1 mixture with no more than two exposures. Publish and cold-verify prepared inputs from the original tokenizer, accepted `R` and `F`. Native dispatch compares the prepared/run config's release, mixture, training path and validation path with the exact accepted release before publication or config binding. A shortage or binding failure stops before any model work. The frozen evaluation profile remains bound to H, not R.

The native `render-declaration` operation is a bounded, exclusive JSON/YAML data write (64 MiB maximum) with exact named substitutions and a hash receipt in the monitored command log. Quoted `*_JSON` slots accept only a parsed JSON array for the reviewed spot-audit and family-merge lists, keeping their checked-in templates valid JSON. It does not execute a template or validate semantic review. Review analysis uses native inventory, audit, lineage and corpus inspection commands; no inline Python, shell pipeline or unmonitored local analysis file is admitted as gate evidence. Agent-assisted reviewer work is recorded separately as active start/end intervals plus item decisions, aggregated against the existing **8 preparation reviewer-hours** and **2 evaluation reviewer-hours**. Process monitors account for local CPU/RSS/storage/time, not remote deliberation. If a reviewer needs an unplanned artifact or cannot substantiate a decision within the allowance, stop and report that specific gap.

The retained evidence names only the *inputs*. New admission, inventory, splits, release, family inventory, measurement, mixture, bundle, run and checkpoint identities do not exist yet. Resolve each from its native receipt and cold verification before the next dependent phase; do not prefill hashes from B13's unsupervised files.
