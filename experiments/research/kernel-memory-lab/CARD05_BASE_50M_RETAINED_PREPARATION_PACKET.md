## Noncyclic preparation order

Let `S` be `uv run --locked --no-sync sparselab --work-dir <common-root>`, `P` the unchanged acquisition project, `A` a **new** exclusive attempt root, `H` the original C03-C1 tokenizer/evaluation release, `R` a future candidate release, and `F` its finalized family inventory. Every mutating native leaf below runs as `S attempt run` with its new ledger, the one whole-attempt monitor, the preparation monitor and the owned supervisor. The preparatory zero-counter reservation is still charged as a phase; a failed phase stops. The existing [packet](CARD05_BASE_50M_LAUNCH_PACKET.md#exact-native-operation-map-and-stop-points) specifies the exact `attempt run` flags and original phase limits. This packet replaces its rights/family/release rows and forbids its live acquisition row.

**Phase path binding after C05-B16.** The checked-in [31-phase map](card05-base-50m/preparation-phase-paths-v1.json) names every supervised preparation phase and its leaf artifact, if any. Derive paths with the read-only native command `S attempt phase-paths --attempt-root A --label <map-phase> [--leaf-name <map-leaf>]` and use its returned `leaf`, `completion` and `inner_monitor` values verbatim. It always places leaf artifacts under `A/prep/`, outer owned receipts under `A/receipts/<phase>.outer-owned.json`, and inner monitor logs under `A/logs/<phase>.inner-monitor/`. Make these three directories before the first phase. The outer dispatcher derives `<completion>.ready`, `<completion>.attempt.json` and `<completion>.monitor/`; all remain in the receipt namespace. A phase without a leaf output omits `--leaf-name`; `cold-verify-mixture` reads the already published `A/prep/mixture`, and cold prepared-bundle verification reads the already published `A/prep/prepared-bundle`. Each later declaration must use the resolved prior leaf path, never a guessed hash. The native dispatcher now checks the parsed leaf output, these derived paths, both monitor trees and protected inputs for canonical aliases and overlapping output trees **before reservation or child launch**. B16's 60 MiB draft, spent ledger and absent outer receipt remain unchanged; its outer receipt-based shutdown is unverified.

Agent-assisted reviewer work is recorded separately as active start/end intervals plus item decisions, aggregated against the existing **8 preparation reviewer-hours** and **2 evaluation reviewer-hours**. Process monitors account for local CPU/RSS/storage/time, not remote deliberation. If a reviewer needs an unplanned artifact or cannot substantiate a decision within the allowance, stop and report that specific gap.

The retained evidence names only the *inputs*. New admission, inventory, splits, release, family inventory, measurement, mixture, bundle, run and checkpoint identities do not exist yet. Resolve each from its native receipt and cold verification before the next dependent phase; do not prefill hashes from B13's unsupervised files.
